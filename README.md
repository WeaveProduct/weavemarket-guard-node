# weavemarket-guard-node

Скрипт защиты ноды **Remnawave**: проверяет открытые порты, настраивает **UFW** и **fail2ban**, оставляет порт ноды открытым только для IP панели и показывает, какие порты Docker торчат в интернет в обход UFW и как их закрыть.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/WeaveProduct/weavemarket-guard-node/main/node-guard.sh)
```

---

## Что делает

| Шаг | Что происходит |
|---|---|
| **1. Аудит** | Таблица всех слушающих портов: процесс, адрес и доступность (localhost / внутренняя сеть / интернет / Docker в обход UFW). Текущий статус UFW и fail2ban |
| **2. Параметры** | Спрашивает SSH-порт, порт ноды и IP панели, затем порты для всех. Почти всё определяет сам и подставляет как значение по умолчанию |
| **3. План** | Показывает, что будет открыто, что закроется, и ждёт подтверждения |
| **4. UFW** | SSH и VPN-порты открыты для всех, порт ноды — только с IP панели, остальное входящее запрещено |
| **5. fail2ban** | Защищает SSH от перебора, повторных нарушителей банит на неделю, IP панели в белом списке |
| **6. Docker** | Находит контейнеры с портами, открытыми в интернет, и для каждого пишет, как закрыть порт |

## Требования

- Debian 11+ или Ubuntu 20.04+
- root
- KVM или выделенный сервер. На OpenVZ/LXC без iptables UFW не включится

Недостающие пакеты (`ufw`, `fail2ban`, `python3-systemd`) скрипт установит сам.

## Быстрый старт

Сначала посмотрите, что открыто на сервере. Этот режим ничего не меняет:

```bash
wget -O node-guard.sh https://raw.githubusercontent.com/WeaveProduct/weavemarket-guard-node/main/node-guard.sh
sudo bash node-guard.sh --audit
```

Затем запустите настройку и ответьте на вопросы:

```bash
sudo bash node-guard.sh
```

Чтобы настроить без вопросов (например, сразу на нескольких нодах):

```bash
sudo bash node-guard.sh --panel-ip 203.0.113.10 --node-port 2222 --ports 443/tcp,8443/tcp -y
```

## Опции

| Опция | Описание |
|---|---|
| `--panel-ip IP[,IP]` | IP сервера панели. Только ему будет доступен порт ноды. Можно указать подсеть (`1.2.3.0/24`) и IPv6 |
| `--node-port PORT` | Порт ноды, к которому подключается панель. Обычно `2222` |
| `--ports LIST` | Порты, открытые для всех: `443`, `443/tcp`, `2053/udp`, `10000:10100/tcp`. `-` — ни одного |
| `--ssh-port LIST` | SSH-порт(ы), если автоопределение ошиблось |
| `--reset` | Сбросить существующие правила UFW без вопроса |
| `--no-reset` | Оставить существующие правила UFW и дописать свои |
| `--no-fail2ban` | Не настраивать fail2ban |
| `--no-rollback` | Отключить страховочный автооткат UFW |
| `--audit` | Только проверка портов и Docker, без изменений |
| `-y`, `--yes` | Без вопросов: значения из флагов или найденные автоматически |
| `-h`, `--help` | Справка |

Порт без протокола (`443`) открывается и для TCP, и для UDP. Для диапазона протокол обязателен.

## Как определяются значения

- **SSH-порт** — из `sshd -T`, из процессов `sshd` в `ss` и по порту вашей текущей SSH-сессии.
- **Порт ноды** — из переменной `NODE_PORT` (или `APP_PORT`) контейнера `remnanode`. Если её нет, из `/opt/remnanode/.env` или `docker-compose.yml`. Иначе `2222`.
- **IP панели** — по активным подключениям к порту ноды: панель держит соединение с нодой. Нужен именно IP сервера панели, а не домен — домен может указывать на CDN.
- **Порты для всех** — те, что слушают снаружи `xray`/`rw-core`, `nginx`, `haproxy`, `hysteria`, `sing-box`, `telemt`, `mtg` и т.п. Если есть сертификаты Let's Encrypt с HTTP-проверкой, добавляется `80/tcp`, чтобы они продлевались.

Остальные публичные порты (например, `rpcbind` на 111) скрипт перечислит и закроет. Если какой-то из них нужен снаружи, допишите его в список портов.

> Если нода ещё не подключена к панели, xray не запущен и его порты не видны. Тогда по умолчанию предлагается `443/tcp` — укажите порты инбаундов из своего профиля.

## Страховка от потери доступа

После включения UFW скрипт просит открыть **новую** SSH-сессию и проверить вход. На подтверждение есть 180 секунд — введите `ok`.

Если подтверждения нет, UFW отключается автоматически. Откат запланирован через `systemd-run`, поэтому сработает, даже если текущая сессия оборвалась.

В режиме `-y` страховка не включается: подтвердить некому.

Если доступ всё-таки потерян, зайдите через VNC-консоль хостера и выполните:

```bash
ufw disable
```

## fail2ban

Скрипт пишет конфиг `/etc/fail2ban/jail.d/node-guard.local`:

- **sshd** — 5 неудачных входов за 10 минут → бан на 1 час. При повторах бан растёт, вплоть до недели
- **recidive** — 3 бана за сутки → бан на неделю по всем портам
- **белый список** — `127.0.0.1`, `::1` и IP панели

Источник логов выбирается сам: `/var/log/auth.log`, если он есть, иначе journald (как на Debian 12+).

## Docker и UFW

Docker сам добавляет правила iptables и пропускает трафик к контейнерам **раньше**, чем до него доходит UFW. Поэтому порт из блока `ports:` в `docker-compose.yml` доступен из интернета, даже если UFW его «закрывает».

`remnanode` работает в `network_mode: host` — на его порты UFW действует как обычно. Проблема касается остальных контейнеров на ноде: страницы подписки, Redis, панели мониторинга и т.п.

Для каждого такого контейнера скрипт показывает готовое исправление:

```
▸ subpage
  в ports: "3010:3010"  →  "127.0.0.1:3010:3010"
  файл:   /opt/subpage/docker-compose.yml   (сервис: remnawave-subscription-page)
  затем:  cd /opt/subpage && docker compose up -d
```

После этого порт слушает только localhost, и к сервису можно ходить через nginx на этом же сервере.

Другие способы:

- **Ограничить доступ по IP**, не трогая compose. Правило работает до перезагрузки:
  ```bash
  iptables -I DOCKER-USER -i eth0 -p tcp -m conntrack --ctorigdstport 3010 --ctdir ORIGINAL ! -s <ВАШ_IP> -j DROP
  ```
  Для постоянных правил через UFW есть утилита [ufw-docker](https://github.com/chaifeng/ufw-docker).
- **Для всех контейнеров сразу** добавьте в `/etc/docker/daemon.json`:
  ```json
  { "ip": "127.0.0.1" }
  ```
  Затем выполните `systemctl restart docker` и `docker compose up -d --force-recreate` в каждом проекте. Порты без явного IP станут слушать только localhost.

## Что меняется на сервере

| Что | Где |
|---|---|
| Правила UFW | `ufw status numbered`. При сбросе бэкап старых правил — `/etc/ufw/*.rules.<дата>` |
| IPv6 в UFW | `IPV6=yes` в `/etc/default/ufw` |
| Конфиг fail2ban | `/etc/fail2ban/jail.d/node-guard.local` |
| Пакеты | `ufw`, `fail2ban`, `python3-systemd` (если не были установлены) |

Docker-контейнеры и их compose-файлы скрипт **не трогает** — только подсказывает, что поменять.

## Полезные команды

```bash
ufw status numbered                     # правила UFW
ufw allow 8443/tcp                      # открыть порт для всех
ufw delete <номер>                      # удалить правило
fail2ban-client status sshd             # кто забанен
fail2ban-client set sshd unbanip <IP>   # разбанить
```

## FAQ

**Сменился IP панели или добавился новый инбаунд.**
Запустите скрипт ещё раз — он пересоберёт правила.

**Панель на нескольких серверах или у неё есть IPv6.**
Перечислите адреса через запятую: `--panel-ip 203.0.113.10,2001:db8::10`.

**Не хочу терять свои правила UFW.**
Запустите с `--no-reset`. Скрипт допишет свои правила и удалит только правило «порт ноды открыт для всех», если такое было.

**Как всё откатить.**
```bash
ufw disable
rm /etc/fail2ban/jail.d/node-guard.local && systemctl restart fail2ban
```
